## [英特尔 EMIB-T 以 50%成本优势挑战台积电 CoWoS](https://www.techpowerup.com/351274/intels-emib-t-to-rival-tsmcs-cowos-with-50-cost-advantage-volume-production-in-2027) ⭐️ 7.5/10

英特尔的 EMIB-T（带硅通孔的嵌入式多芯片互连桥）先进封装技术据称正在吸引包括 Broadcom 和 Meta 在内的外部 ASIC 设计客户，号称相比台积电的 CoWoS 可提供高达 50%的成本优势。据台湾欣兴电子透露，EMIB-T 将于 2027 年实现量产。 这一进展可能颠覆目前由台积电 CoWoS 主导的先进封装市场，CoWoS 一直是 AI 芯片生产的关键瓶颈，需求来自 NVIDIA 等公司。更便宜的替代方案将为超大规模云厂商和 ASIC 设计商提供更多筹码，并有可能缓解 AI 加速器的供应紧张。 EMIB-T 包含硅通孔（TSV），使 ASIC 可直接获取电源连接，从而在单一封装上实现多千瓦级别的解决方案。50%的价格差距主要出现在需要昂贵硅中介层的 CoWoS 变体上（如 CoWoS-L 或 CoWoS-R），而英特尔目前正在 EMIB-T 量产前扩大其标准 EMIB 和 Foveros 产线的产能。

rss · TechPowerUp News · 7月31日 17:51

**背景**: 先进封装技术（如 CoWoS 和 EMIB）使多个芯片裸片（逻辑芯片、内存、HBM）能够集成在单一封装内，这对需要海量内存带宽的现代 AI 加速器至关重要。CoWoS（芯片-晶圆-基板，Chip-on-Wafer-on-Substrate）是台积电的 2.5D 封装技术，使用硅中介层将多个裸片并排连接。EMIB 是英特尔的替代方案，在低成本的有机基板内嵌入微型硅桥，避免了全尺寸硅中介层的成本和面积开销。硅通孔（TSV）是完全穿过硅裸片的垂直电气连接，可实现 3D 堆叠和高效的电力传输。

## [澜起科技启动 CXL 3.2 MXC 芯片试生产，支持 8000 MT/s DDR5](https://www.techpowerup.com/351268/montage-technology-enters-trial-production-of-cxl-3-2-mxc-chip-supporting-8000-mt-s-ddr5) ⭐️ 7.5/10

澜起科技（Montage Technology）宣布启动业界首款 CXL 3.2 内存扩展控制器（MXC）芯片的试生产。该芯片基于 PCIe 6.x 物理层并支持 CXL 3.2 协议，可实现高达 64 GT/s 的数据传输速率，集成双通道 DDR5 控制器，能够驱动 8000 MT/s 的内存。 这一里程碑有助于为 AI 和云计算负载构建更大、更高效的内存池，而传统服务器的 DRAM 容量上限正日益成为瓶颈。通过率先支持 CXL 3.2 搭配 PCIe 6.x，澜起科技在重塑数据中心架构的内存解耦与池化趋势中占据了先发优势。 该 MXC 是兼容 CXL.mem 与 CXL.io 协议的 CXL Type 3 设备，能够将主机端的 CXL 内存请求实时转换为 DDR 命令，作为主机与后端 DRAM 之间的桥梁。需要注意的是，这只是一份描述试生产的新闻稿公告，尚非量产发货，因此实际可获得性与生态验证仍有待观察。

rss · TechPowerUp News · 7月31日 15:07

**背景**: Compute Express Link (CXL) is an open industry-standard interconnect built on the PCIe physical layer that allows processors to coherently attach devices such as accelerators, memory buffers, and persistent memory. CXL Type 3 devices specifically serve as memory expanders that expose DDR5 modules to a host over CXL, enabling memory pooling and disaggregation. CXL 3.0 was published in August 2022, with CXL 3.2 building on the PCIe 6.x physical layer to double the per-lane bandwidth compared to earlier generations. Montage Technology was also the first to commercialize a CXL MXC chip back in 2022, based on CXL 2.0 and PCIe 5.0.

## [CrossOver 发布首个原生 Apple Silicon 预览版，距芯片转型已六年](https://www.solidot.org/story?sid=84978) ⭐️ 7.3/10

CrossOver 发布了首个原生 Apple Silicon 支持预览版，距离苹果发布首款 ARM 架构 Mac 已过去六年。此次发布旨在让 x86 Windows 游戏不依赖 Rosetta 2 即可在 Apple Silicon 上运行，因为苹果计划在 macOS 28 中完全弃用 Rosetta 2。 随着苹果逐步淘汰 Rosetta 2，任何基于 Wine 的兼容工具（包括 CrossOver 和 Steam 的 Proton）若不获得原生 ARM64 支持，将失去在未来 macOS 版本上运行 x86 Windows 软件的能力。CrossOver 的进展为 Apple Silicon 上的 Mac 游戏和 Windows 兼容性指明了更广泛的前进方向。 目前该预览版仅支持通过 DXMT ARM64 运行 DirectX 11 游戏，因为 ARM64 版的 D3DMetal 尚未就绪；这些限制预计将在 CrossOver 27 正式版中解决。CodeWeavers 产品经理 Meredith 在公告中指出，这项工作横跨约四年时间，由 CodeWeavers 工程团队对 Wine 及其周边工具链进行了一系列改进。

rss · Solidot · 7月31日 14:32

**背景**: Wine 是一个开源兼容层，可以让 Windows 应用程序在没有完整 CPU 模拟的非 Windows 系统上运行，它是 Steam Proton 和 CodeWeavers 商业产品 CrossOver 等多个重要项目的基础。苹果于 2020 年随首批 Apple Silicon Mac 一同推出了 Rosetta 2，用于将 Intel (x86_64) 指令动态翻译为 ARM64 指令，使旧应用能够在新芯片上运行。CrossOver 及类似模拟器历来依赖 Rosetta 2 将 x86 Windows 二进制文件翻译后再交由 Wine 处理。Rosetta 2 计划在 macOS 28 中移除，这意味着 Mac 上整个基于 Wine 的技术栈都必须转向原生 ARM64，才能继续运行 x86 Windows 软件。

## [探索电梯调度算法及其现实世界中的低效问题](https://john.fun/elevators) ⭐️ 7.0/10

一篇题为《Elevators》的个人博客文章在 john.fun 上发布，通过交互式模拟探讨了电梯调度算法，在 Hacker News 上获得了 1437 分和 350 条评论。 这篇文章将日常体验与计算机科学概念（如调度算法和系统思维）联系起来，为理解算法设计选择如何影响电梯和计算系统中的现实效率提供了一个易于理解的切入点。 评论中提出的一个关键见解是，SCAN 磁盘调度算法在概念上与电梯调度类似——两者都涉及一个「磁头/轿厢」沿一个方向移动来服务请求。文章还评估了目的地调度系统（Destination Dispatch），发现在某些流量模式下（如模拟的随机目的地），它们的性能可能不如传统系统。

hackernews · Jrh0203 · 7月31日 15:17 · [社区讨论](https://news.ycombinator.com/item?id=49124218)

**背景**: 电梯调度算法是一组规则，用于确定哪部电梯轿厢应响应哪一层的呼叫，从而优化等待时间、运行时间和能耗等指标。常见策略包括分配最近的轿厢、集选控制（在一次行程中同时处理上行和下行呼叫）以及目的地调度（乘客在上车前输入目标楼层，以便系统将前往相近楼层的乘客分组）。SCAN 算法最初是一种磁盘调度技术，其工作原理是让「磁头」沿一个方向连续移动，沿途服务所有请求，然后反向移动——这与经典的电梯系统逻辑相同，即电梯先运行到最高层再改变方向。
