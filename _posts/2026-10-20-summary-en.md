## [Cloudflare announces tsrs, a Rust port of the TypeScript compiler](https://blog.cloudflare.com/typescript-rust-port/) ⭐️ 9.0/10

Cloudflare and the VoidZero team announced tsrs, a high-performance Rust port of the TypeScript compiler that is up to 8x faster and uses 70% less memory than the standard Go-based implementation. The project was specifically engineered to allow the compiler to run inside WebAssembly sandboxes without the need for a full Go runtime environment. This development is significant for web developers because it provides a much faster type-checking tool that can run securely in browser-based or serverless sandboxed environments. It also demonstrates a viable architectural pattern for migrating complex, garbage-collected systems to Rust without relying on a runtime garbage collector. To overcome Rust's lack of a built-in garbage collector, the tsrs project utilizes a custom memory model based on long-lived arenas that are never explicitly freed. This technique effectively simulates garbage collection semantics while maintaining Rust's strict memory safety guarantees and avoiding the runtime overhead of a traditional GC.

hackernews · hnisjafx40 · Oct 20, 13:18 · [Discussion](https://news.ycombinator.com/item?id=50165953)

**Background**: The standard TypeScript compiler is currently written in Go, which requires the entire Go runtime to be exported when compiled to WebAssembly for use in isolated environments. Rust, by contrast, is a systems language that guarantees memory safety at compile time through its ownership model and does not include a built-in runtime garbage collector. This makes porting applications that rely heavily on dynamic object graphs, like compilers, challenging in Rust without custom memory management strategies.

eMudhra, a major Certificate Authority, experienced a critical security compromise because its private keys were single-byte values that were trivially guessable. This failure prompted a broader discussion about the lack of revocation infrastructure in parts of the certificate ecosystem and the varying resilience of different browser vendors. This incident exposes critical key management failures in the Public Key Infrastructure (PKI) ecosystem, highlighting how a single CA can compromise the security of millions of certificates. It underscores the urgent need for robust key generation practices and real-time revocation capabilities to mitigate widespread impact. The compromised private keys were effectively single bytes (such as the value '4'), making them inherently weak and immediately factorable by anyone. While major browser vendors like Mozilla, Apple, and Microsoft could quickly remediate the issue, the rest of the ecosystem lacks the investment in revocation mechanisms to handle such events effectively.

Their security depends on using cryptographically strong, unpredictable private keys, typically generated in secure hardware modules. Browsers rely on revocation mechanisms like CRLs or OneCRL to quickly disable compromised certificates, but these systems vary widely in capability and deployment across different platforms.
