## [NVIDIA Revives Rubin CPX GPU with HBM4 Memory, Drops GDDR7](https://www.techpowerup.com/352213/nvidias-rubin-cpx-gpu-reborn-with-hbm4-memory-no-more-gddr7) ⭐️ 7.5/10

NVIDIA has revived its previously paused "Rubin CPX" AI accelerator project, redesigning it with 168GB of HBM4 memory instead of the originally planned 128GB of GDDR7, according to supply chain analyst Ming Chi Kuo. The chip is targeted at large-scale agentic AI workloads and will be deployed in racks housing 64 to 256 standalone CPX GPUs. This architectural shift from GDDR7 to HBM4 signals NVIDIA's recognition that agentic AI workloads demand much higher memory bandwidth than initially anticipated, potentially reshaping AI infrastructure planning and HBM supply dynamics. The separation of prefill and decode tasks across distinct GPU SKUs reflects a new paradigm in optimizing LLM inference pipelines at rack scale. Each rack tray containing eight CPX GPUs can handle 1.34TB of long-context prefill and associated KV cache using HBM4. Because the original GDDR7-based design did not require HBM4 integration, NVIDIA has had to redesign the package, likely adopting TSMC's CoWoS-S or CoWoS-L advanced packaging technology.

rss · TechPowerUp News · Sep 1, 12:38

**Background**: Agentic AI refers to autonomous AI systems that execute complex, goal-driven tasks with minimal human intervention, requiring massive context windows and extensive memory bandwidth. High Bandwidth Memory (HBM) is a 3D-stacked DRAM technology that delivers far higher bandwidth than traditional memory like GDDR7 by using wide interfaces and vertically stacked dies, at the cost of higher complexity and expense. In LLM inference, the "prefill" phase processes the input prompt in parallel while the "decode" phase generates output tokens sequentially; these two phases have very different compute and memory profiles, motivating NVIDIA's decision to use specialized hardware for each.

## [NVIDIA GPU Frame Interpolation Support Lands in FFmpeg via Vulkan](https://www.techpowerup.com/352206/nvidia-gpu-frame-interpolation-support-lands-in-ffmpeg) ⭐️ 7.5/10

NVIDIA's GPU-accelerated frame interpolation support, leveraging the Optical Flow Accelerator (NVOFA) on GeForce RTX GPUs, has been merged into FFmpeg via a Vulkan API implementation. The integration enables Engine-assisted Frame-rate Up Conversion (FRUC), allowing users to AI-generate intermediate frames to increase video frame rates without involving the traditional graphics rendering pipeline. FFmpeg is one of the most widely used multimedia processing tools in the world, powering platforms like YouTube and countless other services and applications. Adding hardware-accelerated AI frame interpolation to FFmpeg brings efficient, high-quality frame rate upscaling to a massive user base of video editors, content creators, and media processing pipelines. The implementation uses NVENC for encoder-side frame data and the NVOFA hardware to generate motion vectors that describe inter-frame object movement, which are then used to synthesize intermediate frames. The new Vulkan-based approach avoids proprietary software dependencies, which was the reason an earlier 2023 patch failed to be merged into the main FFmpeg codebase.

rss · TechPowerUp News · Sep 1, 07:21

**Background**: Optical Flow is a computer vision technique that analyzes motion between consecutive video frames by calculating how pixels move from one frame to the next. NVIDIA's NVOFA, available starting from the Turing GPU generation, is a dedicated hardware accelerator that computes optical flow and stereo disparity independently of graphics or CUDA cores. Vulkan is an open-standard, cross-vendor GPU API maintained by the Khronos Group, providing high-efficiency access to modern GPUs for both graphics and compute workloads — making it an ideal non-proprietary interface for FFmpeg to access NVIDIA's optical flow hardware.

## [New iPSJ GaN-on-Si transistor withstands nearly 4kV before breakdown](https://www.electronicsweekly.com/news/business/new-transistor-withstands-nearly-4kv-before-breakdown-2026-09/) ⭐️ 7.5/10

Researchers at EPFL's POWERlab have invented an Intrinsic Polarization Super Junction (iPSJ) transistor made from GaN-on-Si that reportedly withstands nearly 4 kV before breakdown. The design exploits intrinsic polarization fields in III-nitride heterostructures to form charge-balanced superjunctions without intentional doping, and the work has been published in Nature Electronics. If validated, this approach could push GaN-on-Si devices into voltage ranges traditionally dominated by silicon carbide (SiC), enabling more compact and efficient high-voltage power converters for EVs, grid, and industrial applications. The use of GaN-on-Si rather than more expensive substrates could also lower manufacturing costs compared to SiC alternatives. The breakthrough relies on intrinsic polarization charges in GaN heterostructures rather than conventional doping to form the superjunction, which has historically been a bottleneck for GaN high-voltage devices. The device was fabricated on a silicon substrate, and the underlying paper is 'Intrinsic polarization superjunctions in III-nitride heterostructures for efficient power electronics' (Nature Electronics, 2026, DOI: 10.1038/s41928-026-01691-4).

rss · Electronics Weekly · Sep 1, 05:17

**Background**: GaN-on-Si transistors are widely seen as a promising technology for next-generation power switching because GaN offers lower switching losses than silicon, and silicon substrates are cheaper than SiC. However, conventional GaN devices struggle to reach very high breakdown voltages because electric field crowding limits scalability. Superjunction technology, originally developed for silicon MOSFETs, overcomes this by creating alternating p- and n-type regions that balance the electric field, but implementing such structures in GaN via doping has been difficult.

## [Softaculous Hit by 33-Hour BGP Route Hijack Targeting Hetzner IPs](https://www.solidot.org/story?sid=85256) ⭐️ 7.3/10

On August 28 at 20:57 UTC, an unrelated network announced BGP routes for Hetzner IP space used by Softaculous, redirecting traffic to attacker-controlled servers for approximately 33 hours. Attackers leveraged the hijack to obtain valid TLS certificates from Let's Encrypt and push a malicious Virtualizor update package to a handful of hypervisor servers. This incident demonstrates how BGP hijacking can bypass domain validation mechanisms, enabling supply-chain attacks against software update infrastructure. Hosting providers, VPS operators, and downstream customers using Virtualizor face credential compromise risks, highlighting the fragility of internet routing security at the infrastructure layer. The hijack occurred in two phases: initial hijack from August 28 20:57 UTC, reported by Softaculous to Hetzner on August 29 08:50 UTC, then a second 10-hour hijack starting August 29 20:00 UTC, finally ending August 30 05:50-06:10 UTC. Let's Encrypt's automated domain validation (likely ACME HTTP-01 challenge) was bypassed because the validation traffic itself was rerouted to attacker IPs, allowing legitimate certificates to be issued.

rss · Solidot · Sep 1, 14:35

**Background**: BGP (Border Gateway Protocol) is the protocol that routes traffic between autonomous systems on the internet. BGP route hijacking occurs when an unauthorized network announces IP prefixes it does not legitimately own, causing traffic destined for those IPs to be rerouted through the attacker's network. Softaculous is a commercial auto-installer library used by web hosting providers to deploy applications like WordPress and Joomla, while Virtualizor is a web-based VPS management panel developed and maintained by Softaculous. Let's Encrypt is a free, automated certificate authority that validates domain ownership via the ACME protocol, typically by checking that the requesting server can respond on a specific HTTP path — a check that becomes meaningless if traffic to that server is being hijacked.
