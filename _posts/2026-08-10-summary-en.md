## [Klepton: Run Android ARM64 VR Apps on Apple Vision Pro](https://github.com/shinyquagsire23/Klepton) ⭐️ 7.0/10

Klepton 是一个开源兼容层，可以在不使用 JIT 编译器的情况下，将原本为 Meta Quest 头显构建的 Android ARM64 VR APK 运行在 Apple Vision Pro 和 macOS 上。它通过将 Android 的 .so 原生库翻译为 Apple 的 dylib，并借助 ANGLE（OpenGL ES 转译）和 MoltenVK（Vulkan 转译）来转发图形调用实现这一目标。 This significantly expands the software library available to Apple Vision Pro users by unlocking the large catalog of Quest VR titles, without requiring Apple to officially support sideloading or third-party VR runtimes. It also demonstrates a viable binary-translation path for ARM64-to-ARM64 translation that avoids the need for a JIT compiler, which is typically restricted on Apple platforms. The translation happens entirely ahead of time rather than at runtime, which sidesteps Apple's JIT restrictions on iOS/visionOS. A noteworthy technical challenge is that Darwin (Apple's kernel) zeroes the x18 register on any exception return, including timer interrupts, meaning Quest apps cannot reliably preserve state in x18 across even a single scheduling window. The project relies on ANGLE and MoltenVK to bridge graphics APIs.

hackernews · LorenDB · Aug 10, 03:12 · [Discussion](https://news.ycombinator.com/item?id=49238818)

**Background**: Apple Vision Pro is a spatial computing headset released in 2024 that runs visionOS, a derivative of iOS. While it supports iPad apps and some 3D content, it has a relatively small native VR app catalog compared to Meta Quest headsets, which run a full Android-based VR operating system. Binary translation layers convert machine code compiled for one CPU architecture or platform into instructions suitable for another; projects like Waydroid's libndk/libhoudini and Berberis/Digitalis have used similar techniques to run ARM Android apps on x86 systems. JIT (Just-In-Time) compilation is a common optimization in these translation layers but is restricted on Apple platforms for security reasons, which makes the JIT-free approach of Klepton particularly notable.
