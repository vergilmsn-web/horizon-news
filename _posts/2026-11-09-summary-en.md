## [Diamond Foundry produces first 200mm single-crystal diamond wafer for AI chip cooling](https://www.tomshardware.com/pc-components/cooling/diamond-foundry-creates-worlds-first-200mm-single-crystal-diamond-wafer-massive-gem-aims-to-solve-ai-chip-cooling-crisis-envisioned-as-a-cooling-material-for-semiconductors) ⭐️ 8.5/10

Diamond Foundry has successfully manufactured a 200mm single-crystal diamond wafer, marking the first time such a large-diameter diamond substrate has been produced. This new wafer is specifically designed to serve as a superior cooling material for high-heat AI processors. As AI chips generate unprecedented heat, thermal management has become the primary bottleneck for high-performance computing. This breakthrough enables efficient heat dissipation, potentially solving the thermal crisis and allowing future AI architectures to operate at higher performance limits. The wafer's single-crystal structure provides superior thermal conductivity compared to polycrystalline alternatives, preventing hotspots on chips. Diamond Foundry has scaled its proprietary manufacturing technology to produce diamond at mining scale without the environmental toll of traditional mining.

rss · Tom's Hardware · Nov 8, 15:25

**Background**: Diamond possesses the highest thermal conductivity of any known solid material, making it an ideal candidate for semiconductor heat spreaders. Historically, diamond wafers were limited to small sizes and high costs, but recent advances in chemical vapor deposition (CVD) technology have allowed for large-scale production. 200mm (8-inch) is a standard size in the semiconductor industry, comparable to silicon wafers.

## [Outlook.com begins silently rejecting email from domains without DMARC](https://mailroute.net/blog/outlook-rejecting-email-without-dmarc) ⭐️ 7.0/10

Outlook.com has started rejecting incoming emails from domains that do not have a DMARC record published, marking a major enforcement step by Microsoft. This move is largely silent, meaning senders may not receive clear feedback if their email is blocked. This change will significantly impact email deliverability, forcing all senders, especially small businesses and self-hosted mail administrators, to adopt DMARC. It sets a new de facto standard for email security, making spoofing and phishing harder by requiring domain authentication. Microsoft also maintains non-public blocklists that can reject valid mail, causing frustration for admins who cannot easily delist themselves. Some users report silent rejection logs where Outlook accepts the message at the connection level but fails to deliver it to the inbox.

hackernews · xmddmx · Nov 8, 19:20 · [Discussion](https://news.ycombinator.com/item?id=50416158)

**Background**: DMARC (Domain-based Message Authentication, Reporting, and Conformance) is an email authentication protocol that builds on SPF and DKIM to allow domain owners to control and monitor how email sent from their domain is treated. It helps prevent domain spoofing by specifying a policy for handling unauthenticated mail, such as quarantining or rejecting it.

Dux, formerly known as Dank Material Shell (DMS), has rebranded and matured into a robust Wayland desktop shell. It recently added official support for atomic Linux distributions like Bazzite and features a file manager and theming capabilities. This development lowers the barrier for users of popular immutable distros to adopt Niri and custom Wayland setups without the previous installation friction. It signals that lightweight, highly customizable Wayland shells are becoming more mainstream and production-ready. Dux is built with Quickshell and Go, providing a unified interface for window and notification management. It is compatible with multiple Wayland compositors, including Niri, Hyprland, Sway, and River-based systems.

hackernews · indigodaddy · Nov 8, 19:08 · [Discussion](https://news.ycombinator.com/item?id=50416053)

**Background**: Wayland is a modern display server protocol that replaces the aging X11 system, offering better performance and security for Linux desktops. A desktop shell is the user interface layer that allows users to interact with these compositors, similar to GNOME Shell or KDE Plasma. Atomic or immutable Linux distributions keep the system files read-only to prevent updates from breaking the OS.

## [Paul Ford Argues Web Browsers Can Replace Native Applications](https://ftrain.com/aboard-the-web-is-more-than-enough) ⭐️ 6.0/10

Paul Ford published an opinion piece arguing that the modern web browser is sufficiently powerful to replace native applications for most tasks. Community members, including Simon Willison, supported this view by citing the rapid advancement of web APIs like WebAssembly and three.js. This perspective is significant for the software ecosystem because it highlights the declining cost of development and access barriers when building desktop-class features on the web. It encourages developers to reconsider the need for native tooling and highlights the maturity of frontend technologies. Proponents note that features like offline storage, Server-Sent Events (SSE), and WebAudio are now routinely used multiple times per week to build complex applications. However, critics argue that browsers can become overly bloated, similar to systemd, and that some tasks remain better suited for native applications.

hackernews · edward · Nov 8, 19:48 · [Discussion](https://news.ycombinator.com/item?id=50416456)

**Background**: Traditionally, developers built software for specific operating systems, requiring distinct codebases for macOS, Windows, and Linux. The evolution of web standards and browsers has allowed them to deliver sophisticated, cross-platform experiences without native installation. Technologies like WebAssembly enable running high-performance code directly in the browser.

**Discussion**: The community is divided, with users like Simon Willison enthusiastically validating the thesis by building features on modern web APIs multiple times a week. Others express concern that browsers are becoming overly complex and intrusive, comparing them unfavorably to systemd. A meta-comment notes that the majority of HN users are web developers who naturally lean towards frontend frameworks.
