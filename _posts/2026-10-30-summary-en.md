A security researcher has documented five distinct cross-tenant compromise vectors in Microsoft Azure. These findings highlight critical flaws in the platform's isolation and authentication mechanisms that allow unauthorized access across different organizational tenants. The compromises demonstrate that tenant boundaries in Azure can be bypassed, which threatens the security of multi-tenant cloud environments. This poses a significant risk for enterprises relying on Azure to isolate their data and identities from partners and external users. A specific vulnerability allows an attacker to forge a callback in the admin consent flow if they know the target tenant's ID. Additionally, issues such as path traversal and IDOR may have been exploitable since the initial implementation of these features.

**Background**: In multi-tenant cloud platforms like Azure, logical boundaries separate different customers' data and resources within a shared physical infrastructure. Cross-tenant compromise occurs when an attacker in one tenant bypasses these logical boundaries to access resources in another tenant. This type of vulnerability is highly critical because it breaks the foundational promise of cloud isolation.
